# Security Policy

## Supported Versions

Security updates and vulnerability patches are actively provided for the following versions:

| Version | Supported          |
| :------ | :----------------- |
| 1.0.x   | Yes                |
| < 1.0.0 | No                 |

---

## Reporting a Vulnerability

The security and integrity of **INSPIRE Security Suite** is a top priority. If you discover a potential security vulnerability, weakness, or flaw in this project, we appreciate your help in disclosing it to us responsibly.

> [!IMPORTANT]
> **Please do NOT report security vulnerabilities via public GitHub Issues, Discussions, or social media.**

### Responsible Disclosure Process

1. **Private Advisory / Email Notification**:
   * Please submit a report through GitHub's [Private Vulnerability Reporting](https://github.com/) feature if enabled on this repository, or email the maintainer directly.
   * Provide a detailed summary of the vulnerability, including:
     * Vulnerability classification (e.g. Remote Code Execution, SSRF, Command Injection, Denial of Service).
     * Exact steps to reproduce the issue (proof-of-concept script, sample request payload, or target configuration).
     * Assessment of potential impact and severity.
     * Suggested fix or remediation (if available).

2. **Response Timeline Commitment**:
   * **Acknowledgment**: We aim to acknowledge receipt of your vulnerability report within **48 hours**.
   * **Validation & Assessment**: We will assess the report and confirm the vulnerability within **5 business days**.
   * **Resolution & Patching**: A security patch will be prepared and released promptly (typically within **14 calendar days**).
   * **Public Disclosure**: Once a patch is published, an advisory and release note will be published, giving credit to the reporter (if desired).

## Ethical & Authorized Usage Policy

**INSPIRE** is built strictly for authorized security auditing, educational research, defensive hardening, and penetration testing on systems where you have **explicit, written authorization**. 

The maintainers and contributors are not responsible for any unauthorized misuse, damage, or illegal activities conducted with this tool. Always ensure compliance with local and international cyber laws before executing security assessments against third-party systems.
